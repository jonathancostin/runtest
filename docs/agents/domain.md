# Domain docs

This is a single-context repository.

Before exploring or changing the codebase:

- Read the root `CONTEXT.md` when it exists.
- Read relevant decisions under `docs/adr/` when that directory exists.
- Proceed silently when either location has not been created yet.

Use the terms defined in `CONTEXT.md` throughout issues, plans, tests, and implementation. Do not replace defined terms with synonyms.

If proposed work contradicts an existing ADR, identify the conflict instead of silently overriding the recorded decision.

The domain documentation layout is:

- `CONTEXT.md` for the project glossary and domain model.
- `docs/adr/` for durable system decisions.
- `docs/agents/` for engineering-skill configuration.
